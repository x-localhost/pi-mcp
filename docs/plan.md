## Contract

- Node ESM package using official MCP SDK over stdio; seven tools: `pi_health`, `pi_delegate`, `pi_status`, `pi_result`, `pi_list`, `pi_cancel`, `pi_followup`. Match corresponding Claude input fields and bounds; allow optional provider/model/thinking selection for Pi. Document authentication/engine-specific differences honestly.
- New jobs start from a committed Git ref in a dedicated branch/worktree, preserve dirty source and all failed/cancelled artifacts. Validate absolute canonical repository roots against configured allowedRoots, including symlink escapes. Followup reuses its parent's worktree and session; preserve parent results and exclude concurrent writers to that worktree.
- Detached worker survives MCP disconnect. Atomic private state, cross-process submission lock, idempotent request IDs with conflicting payload rejection, bounded concurrency, deadline/turn limits, graceful abort then process-group termination, truthful terminal states and interrupted-worker recovery. Results include bounded text, error, usage, progress, tracked diff and untracked inventory.
- Pi JSONL RPC is LF-framed with response correlation; completion requires `agent_settled` (not prompt acknowledgement or `agent_end`). Provider errors, unexpected exit, abort, and limits must never masquerade as success. Persist exact session path and validate session resume. No ambient project extensions/MCP/tools loaded.
- Permission enforcement: explicit Pi policy extension, review only read/grep/find/ls; implement additionally write/edit and administrator-configured exact shell commands. Reject filesystem escapes/symlinks and changes to Git administration/state/policy. Shell allowlist is exact commands, no prefix matching. Trusted approved commands may execute repository code; not an OS sandbox. Denials retained in job result. No arbitrary MCP-exposed shell capability.
- Corporate network config: HTTP_PROXY/HTTPS_PROXY/ALL_PROXY/NO_PROXY (upper/lower case), custom CA propagated using NODE_EXTRA_CA_CERTS/GIT_SSL_CAINFO/npm cafile, internal npm registry, provider env allowlist, optional models.json and auth.json paths. Never disable TLS verification. Separate HTTP proxy transport from LLM base URL. Keep standard Git credential helpers/SSH agent usable without logging credentials. Support local cloned corporate repositories and documented proxy-aware clone/setup; no auto clone/push/publish.
- `src/config.mjs` exports `loadConfig(file = process.env.PI_MCP_CONFIG)`, `validateConfig(raw, configDir)`, `buildChildEnv(config, source = process.env)`, `redact(value, sourceEnv = process.env)`, `healthConfig(config, source = process.env)`. Config fields: absolute `piPath`, optional `piArgs` (for node+CLI launch), absolute `stateDir`, nonempty absolute `allowedRoots`, `maxConcurrent` default 2 (1..8), `defaultTimeoutSeconds` 1800, `maxTimeoutSeconds` 7200, `defaultMaxTurns` 30 (1..100), optional `provider`, `model`, `thinkingLevel`, `agentDir`, `modelsFile`, `authFile`, `allowedCommands` string[] default [], `envAllowlist` string[] default [], `network` object with optional `httpProxyEnv`, `httpsProxyEnv`, `allProxyEnv`, `noProxyEnv` (names of environment variables only), `caFile`, `npmRegistry`. Config references secrets by env names; no values in snapshots. `redact` recursively masks credential-like keys, secret env values, proxy URL userinfo, bearer tokens; raw logs and public error paths must use it. `healthConfig` returns only booleans/names/redacted configuration. Configuration validation fails closed for unknown/risky fields and disallowed TLS/env injection overrides.
- Runtime owns copying only approved configuration/auth into a private per-job Pi agent directory (never logs auth), disables auto network/catalog/telemetry and ambient extensions/skills/MCP/project trust, installs policy explicitly. Followups retain isolated identity/settings. `pi_health` checks executable/version, config/credential presence without model requests; presence is not proof of successful authentication.
