## Proposed security contract (independent review before implementation)

- Run the entire MCP server, Pi, Git hooks and allowed shell descendants inside an unprivileged Linux Docker container with `network_mode: none`, all capabilities dropped, no-new-privileges, read-only application/root filesystem, bounded writable state/workspace/tmp, no host HOME/SSH agent/Docker socket/devices, no published ports. No host-execution or normal-network fallback. Existing no-MCP/no-extensions/no-skills startup and tool policy remain in force.
- A dedicated loopback relay in that container forwards bytes ONLY to a fixed Unix socket mounted from a separate gateway container. The agent has no network interface except loopback; raw TCP/UDP, DNS, proxy removal, arbitrary binaries or detached descendants cannot directly reach outside.
- Gateway is an HTTPS reverse proxy for ONE approved OpenAI-compatible Chat Completions endpoint, not a general CONNECT/HTTP forward proxy. It accepts only `POST /v1/chat/completions`, streams the response and never follows redirects. Its upstream URL, private fixed IPv4 address, port, trusted CA and configured header references come from a private read-only administrator configuration. TLS certificate/hostname verification stays enabled. Reject public/loopback/link-local/multicast addresses, wildcard endpoints, userinfo, query/fragment and executable credential values. Connect using the pinned address without DNS resolution. Agent-supplied Host/Authorization/proxy or forwarding headers must not override upstream settings. No arbitrary target/path via request payload or headers; malformed methods/CONNECT/upgrade/routes fail closed.
- Credentials remain in the gateway container's environment; Pi uses a non-secret placeholder key and loopback base URL. Reuse existing non-executing header syntax as appropriate; do not print request bodies, headers, credentials or upstream error content to diagnostics. Gateway has no workspace/state mount. Agent Unix-socket volume is read-only (connect permission only). Only HTTPS upstream supported initially; direct corporate route to the pinned address required. Corporate forward-proxy-only routing is a documented unimplemented acceptance constraint unless user requires it.
- Default allowlist has no configured upstream (fail closed); administrator must supply real private address, HTTPS hostname, corporate CA and header names outside committed examples. Allow only configured non-loopback private RFC1918 IPv4, explicit ports. Do not infer that private address alone proves corporate ownership. Approved LLM service itself must be trusted and configured without server-side Internet search/third-party routing; this client cannot verify its backend behavior.
- Provide Docker build/runtime configuration, agent and gateway entrypoints, examples and Korean Claude Code MCP registration instructions using a persistent agent container plus `docker compose exec -T agent ...`. No exposed HTTP listener on the host. Lifecycle/health checks verify relay/gateway ready before exposing MCP; server processes share persistent private state inside the agent container so disconnects do not kill jobs. Explicit stop stops the whole sandbox. Health/launch instructions must not claim normal host execution is isolated.
- Bound request headers/body size, connection/request/idle timeouts and concurrency. Reject OpenAI built-in external-search options; only ordinary function tool definitions are accepted (Pi's existing local tools). Gateway only exposes the approved LLM endpoint. Permit streaming and custom corporate headers without leaking secrets to model tools.
