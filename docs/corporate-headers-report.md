## Result and design

- `src/headers.mjs` validates Pi 1.4.0 provider `headers`, `models[].headers`, and the distinct `modelOverrides[modelId].headers`. It checks every map's syntax, but resolves references only for the selected provider/model, with provider headers resolved first. The scanner treats a closed invalid `${...}` as one literal; an unclosed `${` leaves its dollar literal and still scans later references, matching installed Pi. Exact-name `models[].headers` entries replace `modelOverrides` entries before resolution. The scanner never recursively expands env values and rejects bytes outside the HTTP header value range. A shared collector covers literal, referenced and compound header secrets using saved `auth.json` env precedence (API key: provider/model; OAuth: provider only).
- `src/manager.mjs` rejects malformed source/owned JSON generically before job allocation, checks headers on new submissions, records which owned files must exist for the worker, and redacts free-form public fields while preserving trusted generated task handles, paths, status, timestamps and counters. Fresh Manager instances use owned credentials for result redaction.
- `src/worker.mjs` fails closed on malformed, unreadable, or unexpectedly missing owned configuration before Pi starts. Worker redaction uses the same header-secret collector. `src/sanitize.mjs` masks complete known secrets before generic Bearer/URL patterns, including quoted, spaced, JSON-escaped, overlapping, and `[redacted]`-prefixed values without corrupting an existing marker.
- The Korean guide explains environment forwarding, optional model overrides, mock-verified Bearer/custom Authorization, API streaming/tool compatibility and safe `agent/models.json` replacement preserving OAuth. Example config uses only generic header names whose real values must be supplied by the operator. Real corporate acceptance remains unverified.
